## 提言v.1.0

## 提案要旨

東京都における生成AI技術の戦略的活用として、都民サービスの質の向上と行政業務の効率化を両立させるAIチャットボット活用の施策を提示する。技術発展に伴い、AIチャットボットのできることや精度は上昇中で、実際に海外の自治体や行政でも事例が多く出てきている。中でも「全庁横断型窓口」の設置と、「観光情報APIの提供による民間サービス促進」は特に投資対効果が高く、行政サービスの向上と経済活性化に貢献する。

1.  **施策1：全部局横断型AI問い合わせ総合窓口の導入**  
    都庁全体の問い合わせ業務を統合し、生成AIを活用した24時間対応の総合窓口を構築。音声・多言語・マルチモーダル対応も視野に入れる。
2.  **施策2：東京都観光情報APIの整備・提供と民間活用促進による観光DX**  
    都が信頼性の高い観光データベースとAPIを整備・提供し、民間事業者がこれを活用して多様なAIチャットボットや観光アプリ等を開発。観光客の利便性向上と地域経済活性化を目指す。

これらの施策は、都民・事業者・観光客とのコミュニケーション効率化とサービス向上に寄与し、職員業務の負担軽減や政策立案の高度化という波及効果も見込まれる。

## 施策１：全部局横断型AI問い合わせ総合窓口の導入

### 何をするかの概要

都庁内の各局・各部門がそれぞれ保有するFAQや問い合わせ対応情報を統合し、都民・法人・非日本語話者がいつでも気軽に利用可能なAI総合窓口を設置する。

### 何をするか具体的に

- 都庁HPやFAQデータをベクトル化し、RAG構成により根拠付きで回答生成
- チャット・音声・LINE等のUIで24時間対応可能にする
- 多言語対応、自動翻訳機能により非日本語話者も利用可能
- 音声対応により高齢者・障害者にも対応
- 問い合わせは録音・蓄積し、ログを分析して政策立案に活用(都民の関心領域・課題の可視化)＆FAQ更新負担を軽減
- AIで難しい案件はAIだけで完結させず、人間オペレーターに引き継ぐ体制を整備
- 親和性の高いキャラクター設計による対話・共感をするというアイデアもあり

### その提案が良い理由

- 年間10万件超の問い合わせのうち最大50%（=5万件）を自動化でき、職員対応約5,000時間の削減効果（1件5分換算）
- 都民が局の縦割り構造を意識せず相談可能になる（総合行政相談への進化）
- 情報格差・言語バリアを解消するインクルーシブな行政窓口
- ログデータから都民の関心・ニーズを可視化し、施策立案に反映
- 市民がAI総合窓口に気軽に相談できることで、行政施策に対する理解促進につながりうる

### 既存のAIチャットボット窓口との違い

Web上で個別のFAQやチャットボットをつなぐ既存の"総合案内"とは違い、行政窓口それ自体を代替し、東京都全体の行政コミュニケーション基盤を再構築する構想である点が大きく異なる。

| 観点 | チャットボット総合案内（既存） | 全部局横断AI窓口（提案） |
|------|-------------------------------|-----------------------------|
| 回答方式 | 各局のFAQや個別Botにリンク誘導 | 単一AIが横断的に回答（RAG） |
| データ統合 | なし（局ごと） | FAQ・HP情報を統合・ベクトル化 |
| 対応UI | Webベース（PC中心） | チャット・音声・LINEなど多様 |
| 言語対応 | 日本語中心 | 多言語＋自動翻訳 |
| 政策活用 | 特になし | ログ分析→関心の可視化・政策反映 |
| エスカレーション | なし | 人(都の担当職員)との連携体制あり |
| キャラクター性 | なし | 対話に親しみや共感を持たせる可能性 |

- 構造面の違い：これまでの東京都の取り組みは、各局や各事業が独立してチャットボットを導入。全庁横断型

### インパクト

- 削減時間：8.4万件×5分＝42万分＝7,000時間
- 年間人件費換算：約1,400万円程度（時給2,000円想定）
- +α：ログデータから都民の関心・ニーズを可視化できることによる政策立案コスト削減
- 算出根拠
   - 東京都内の行政問い合わせ件数：年間約12万件（東京都統計より）
     - [https://www.spt.metro.tokyo.lg.jp/tosei/hodohappyo/press/2022/11/30/01.html](https://www.spt.metro.tokyo.lg.jp/tosei/hodohappyo/press/2022/11/30/01.html)
   - 自動化対象割合：70%
   - 1件あたりの対応時間：5分

### コスト

- 初期費用：3,000万円（RAG構成、マルチモーダルUI構築含む開発費）
- 年間運用費：1,000万円（サーバー/ベンダー保守/API利用料/メンテナンス）
- 試算根拠：生成AI×RAG型チャットボット（都庁規模）の導入相場、および先行自治体事例より

### 想定されるリスクとその対処方法

| リスク          | 対処方法                          |
| ------------ | ----------------------------- |
| 誤答（ハルシネーション） | 制度が向上し続けている最新LLMの使用。RAG構成により公式情報の引用ベースで生成。根拠提示の徹底。都庁HPの深層階層まで読み取り可能にすることで、FAQ更新負担を軽減。 |
| 多言語誤訳        | 自動翻訳＋言語別テンプレート整備、専門監修         |
| 情報更新の遅れ      | 自動クロール・職員による定期チェック体制          |
| 高齢者のデジタル対応困難 | 既存の窓口を無くすわけではない    |
| プライバシー懸念     | 個人情報入力を制限、ログ保存期間を短く設定       |

### 事例（海外・国内）

- 深圳市：DeepSeek大規模モデルを市全域に導入し、行政・生活支援のAI窓口を整備
   -  [深圳市の事例](https://www.sz.gov.cn/cn/xxgk/zfxxgj/zwdt/content/post_12004270.html)
- 渋谷区：111言語対応のAI総合チャットボットを導入（RAG構成）
   - [渋谷区の事例](https://www.showcase-tv.com/pressrelease/20221111-cx-shibuya/)
- 会津若松市：LINE上の行政案内Bot「ちゃチャット」により、ごみの分別や休日・夜間診療、防災関連の情報を24時間提供
   -　[会津若松市の事例](https://www.city.aizuwakamatsu.fukushima.jp/faq/)
   -  [デジタル防災サービスの開始](https://aizuwakamatsu.mylocal.jp/article?articleId=67d7baffa229ac6ba51c7fed)

## 施策２：東京都観光情報APIの整備・提供と民間活用促進による観光DX

### 何をするかの概要

**東京都は、信頼性が高く網羅的な観光データベースを構築し、これをAPI（Application Programming Interface）として広く民間事業者に提供します。** 民間事業者はこのAPIを活用し、自由な発想でAIチャットボット、観光アプリ、Webサービスなどを開発・提供します。これにより、多様な観光客のニーズに応える質の高い情報提供を実現し、観光体験の向上と地域経済の活性化を目指します。

### 何をするか具体的に

**東京都の役割:**

*   **観光データベースの構築・更新:** 都内の観光スポット、イベント、グルメ、宿泊、交通（都営交通等）、文化施設、バリアフリー情報などを集約し、正確かつ最新の状態に保ちます。
*   **高品質APIの開発・提供:**
    *   上記データベースにアクセスするための標準化されたAPIを開発・公開します。
    *   多言語対応（名称、説明文など）のデータを整備します。
    *   位置情報連携、リアルタイム情報（混雑状況など、可能な範囲で）の組み込みも目指します。
    *   安定稼働とセキュリティを担保します。
*   **民間活用促進:**
    *   APIの仕様書、利用ガイドラインを公開します。
    *   民間事業者向けの説明会や、API活用を促進するための開発コンテストなどを開催します。
    *   必要に応じて技術的なサポートを提供します。
*   **データ分析と政策活用:** APIの利用状況や、許諾を得た範囲での利用データを分析し、観光政策の立案・改善に活用します。

**民間事業者の役割 (期待されること):**

*   東京都提供のAPIを活用し、AIチャットボット、観光案内アプリ、Webサイト、デジタルサイネージ用コンテンツなど、**多様な観光情報サービスを開発・提供**します。
*   各社の強み（特定のターゲット層、独自のUI/UX、付加価値の高い機能など）を活かした、**魅力的で競争力のあるサービス** を展開します。
*   ユーザーの趣味嗜好や現在地に応じたパーソナライズ、レコメンデーション機能などを実装します。

### その提案が良い理由

*   **民間活力の最大化:** 民間企業の自由な発想と開発力を活かし、多様で質の高い観光サービスが迅速に生まれる土壌を作ります。都が単独で開発するよりも、幅広いニーズに対応できます。
*   **情報の信頼性と公平性の担保:** 都が公式情報を集約しAPIとして提供することで、民間サービスで利用される情報の正確性と信頼性を底上げします。特定の事業者に偏らない公平な情報基盤となります。
*   **開発・運用コストの最適化:** 都は情報基盤（API）の整備・運用に注力し、サービス開発の大部分は民間が担うため、都全体のコストを最適化できます。
*   **多様なニーズへの対応:** 民間事業者がそれぞれのターゲットに向けてサービス開発を行うことで、言語、目的、デバイス、アクセシビリティなど、多様化する観光客のニーズにきめ細かく対応できます。
*   **データ利活用の促進:** 標準化されたAPIを通じて、都が持つ観光関連データが広く活用され、新たな価値創出につながります。都は利用データを政策決定に活かせます。
*   **持続可能なエコシステム:** 都が情報基盤を提供し続けることで、民間事業者が安定的にサービスを提供・改善できる環境を構築します。

### なぜ観光案内分野なのか (API提供の意義)

*   観光情報は**更新頻度が高く、多岐にわたる**ため、都が一元的に信頼性の高い情報を集約・提供する価値が高い分野です。
*   位置情報、リアルタイム情報など、**技術的な連携要素**が多く、標準化されたAPIが民間開発を促進します。
*   国内外の多様な観光客に対応するため、**多言語対応**のデータ基盤整備が不可欠であり、これを都が担う意義があります。
*   民間サービスが多様化することで、**観光客の満足度向上と消費行動の活性化**に繋がりやすく、地域経済への波及効果が期待できます。

### インパクト

*   **都の業務効率化（間接的な時間削減）:**
    *   API活用サービスが普及することで、観光案内所や各施設への基本的な問い合わせが削減される効果が期待されます。仮にAPI経由で年間数十万件レベルの疑問が解決されれば、数千〜数万時間規模の間接的な業務削減効果が見込めます。（※直接的なチャットボット対応時間の削減ではなく、情報流通改善による効果）
*   **経済効果（民間サービスによる波及効果）:**
    *   信頼できる情報に基づいた魅力的な民間サービスが増えることで、観光客の満足度が向上し、滞在時間の延長や消費額の増加が期待されます。具体的な金額の試算は民間サービスの普及度合いによりますが、大きな経済波及効果が見込めます。
    *   API活用ビジネスという新たな市場創出にも繋がります。
*   **+α:**
    *   都民や観光客が必要な情報に容易にアクセスできるようになり、利便性が向上します。
    *   API利用データ分析による、より効果的な観光政策の立案が可能になります。

### コスト

*   **初期費用:** 5,000万円〜1億円（観光データベース構築、多言語対応、高品質API開発費用）
    *   *試算根拠:* 既存データの集約・整理、新規DB構築、多言語化対応、堅牢なAPI基盤開発には相応の投資が必要。官公庁向け大規模システム開発費を参考に推定。
*   **年間運用費:** 2,000万円〜3,000万円（サーバー費用、データ更新・保守体制、API運用監視、民間サポート体制）
    *   *試算根拠:* 高可用性・高信頼性が求められるAPIの運用保守、継続的なデータ更新、多言語対応維持、サポート人件費等を考慮。

### 想定されるリスクとその対処方法

| リスク                             | 対処方法                                                                                                                               |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| APIの品質・安定性不足                | 十分な技術検証とテスト、段階的な公開、SLA（Service Level Agreement）の設定、監視体制の強化、フィードバックに基づく継続的改善。                     |
| データ鮮度・正確性の維持          | 各所管部署との連携によるデータ収集・更新フローの確立、自動クローリング技術の活用（補助的）、利用者からのフィードバック受付体制。                  |
| セキュリティ・不正利用リスク         | 堅牢な認証・認可システム、アクセス制御、利用状況モニタリング、不正利用検知・対策、脆弱性診断の定期的な実施。                                   |
| 民間事業者のAPI利用が進まない      | APIの使いやすさ（ドキュメント、SDK提供等）、積極的な広報・プロモーション、開発者コミュニティ形成支援、インセンティブ（コンテスト等）の付与。       |
| 民間サービスにおける情報格差・品質差 | API利用ガイドラインで推奨事項（例：アクセシビリティ配慮）を示す。優良なサービス事例の紹介。ただし、基本的には市場原理に委ねる。                      |
| 個人情報・プライバシーへの懸念     | API仕様として個人情報を扱わない設計を徹底。統計的な利用データに関しても匿名化処理を施す。                                                   |

### 事例（オープンデータ/API提供）

*   **公共交通オープンデータ協議会 (ODPT):** 日本全国の公共交通データ（時刻表、運行状況等）を標準化しAPIで提供。多くの乗換案内サービス等が活用。
    *   [https://www.odpt.org/](https://www.odpt.org/)
*   **G-Ports (港湾物流API):** 国土交通省が港湾関連手続きやコンテナ情報をAPIで提供し、物流業界のDXを推進。
    *   [https://www.ks.japortis.jp/](https://www.ks.japortis.jp/)
*   **デジタル庁オープンデータ:** 様々な政府統計データなどをAPI提供。
    *   [https://www.digital.go.jp/policies/open_data/](https://www.digital.go.jp/policies/open_data/)
*   *(海外参考)* **Transport for London (TfL) API:** ロンドン交通局が交通情報をAPIで無料公開し、数百のアプリが開発され、市民・観光客の利便性向上に貢献。
    *   [https://tfl.gov.uk/info-for/open-data-users/](https://tfl.gov.uk/info-for/open-data-users/)
