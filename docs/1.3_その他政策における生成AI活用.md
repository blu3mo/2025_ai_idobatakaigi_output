## 提言v.1.0

## 提案要旨

東京都における生成AI技術の戦略的活用として、都民サービスの質の向上と行政業務の効率化を両立させるAI活用の施策を提示する。特に、**問い合わせ対応の効率化**と**観光分野におけるデータ活用**は、都民・来訪者へのサービス向上と経済活性化に大きく貢献すると期待される。

1.  **施策1：全部局横断型AI問い合わせ総合窓口の導入**  
    都庁全体の問い合わせ業務を統合し、生成AIを活用した24時間対応の総合窓口を構築。音声・多言語・マルチモーダル対応も視野に入れる。**(業務時間削減効果: 約7,000時間/年)**
2.  **施策2：民間主導の観光DXを加速するデータ連携基盤の整備**  
    **民間企業が多様なAI観光案内サービスを開発できるよう、東京都が保有する高品質な観光関連データのAPIを整備・公開する。これにより、イノベーションを促進し、観光客の満足度向上と地域経済活性化を目指す。**

これらの施策は、都民・来訪者サービスの向上、行政の効率化、そして民間活力の促進に寄与するものである。

## 施策１：全部局横断型AI問い合わせ総合窓口の導入

### 何をするかの概要

都庁内の各局・各部門がそれぞれ保有するFAQや問い合わせ対応情報を統合し、都民・法人・非日本語話者がいつでも気軽に利用可能なAI総合窓口を設置する。

### 何をするか具体的に

- 都庁HPやFAQデータをベクトル化し、RAG構成により根拠付きで回答生成
- チャット・音声・LINE等のUIで24時間対応可能にする
- 多言語対応、自動翻訳機能により非日本語話者も利用可能
- 音声対応により高齢者・障害者にも対応
- 問い合わせは録音・蓄積し、ログを分析して政策立案に活用(都民の関心領域・課題の可視化)＆FAQ更新負担を軽減
- AIで難しい案件はAIだけで完結させず、人間オペレーターに引き継ぐ体制を整備
- 親和性の高いキャラクター設計による対話・共感をするというアイデアもあり

### その提案が良い理由

- 年間10万件超の問い合わせのうち最大50%（=5万件）を自動化でき、職員対応約7,000時間の削減効果（1件5分換算）
- 都民が局の縦割り構造を意識せず相談可能になる（総合行政相談への進化）
- 情報格差・言語バリアを解消するインクルーシブな行政窓口
- ログデータから都民の関心・ニーズを可視化し、施策立案に反映
- 市民がAI総合窓口に気軽に相談できることで、行政施策に対する理解促進につながりうる

### 既存のAIチャットボット窓口との違い

Web上で個別のFAQやチャットボットをつなぐ既存の"総合案内"とは違い、行政窓口それ自体を代替し、東京都全体の行政コミュニケーション基盤を再構築する構想である点が大きく異なる。

| 観点 | チャットボット総合案内（既存） | 全部局横断AI窓口（提案） |
|------|-------------------------------|-----------------------------|
| 回答方式 | 各局のFAQや個別Botにリンク誘導 | 単一AIが横断的に回答（RAG） |
| データ統合 | なし（局ごと） | FAQ・HP情報を統合・ベクトル化 |
| 対応UI | Webベース（PC中心） | チャット・音声・LINEなど多様 |
| 言語対応 | 日本語中心 | 多言語＋自動翻訳 |
| 政策活用 | 特になし | ログ分析→関心の可視化・政策反映 |
| エスカレーション | なし | 人(都の担当職員)との連携体制あり |
| キャラクター性 | なし | 対話に親しみや共感を持たせる可能性 |

- 構造面の違い：これまでの東京都の取り組みは、各局や各事業が独立してチャットボットを導入。全庁横断型

### インパクト

- 削減時間：8.4万件×5分＝42万分＝7,000時間
- 年間人件費換算：約1,400万円程度（時給2,000円想定）
- +α：ログデータから都民の関心・ニーズを可視化できることによる政策立案コスト削減
- 算出根拠
   - 東京都内の行政問い合わせ件数：年間約12万件（東京都統計より）
     - [https://www.spt.metro.tokyo.lg.jp/tosei/hodohappyo/press/2022/11/30/01.html](https://www.spt.metro.tokyo.lg.jp/tosei/hodohappyo/press/2022/11/30/01.html)
   - 自動化対象割合：70%
   - 1件あたりの対応時間：5分

### コスト

- 初期費用：3,000万円（RAG構成、マルチモーダルUI構築含む開発費）
- 年間運用費：1,000万円（サーバー/ベンダー保守/API利用料/メンテナンス）
- 試算根拠：生成AI×RAG型チャットボット（都庁規模）の導入相場、および先行自治体事例より

### 想定されるリスクとその対処方法

| リスク          | 対処方法                          |
| ------------ | ----------------------------- |
| 誤答（ハルシネーション） | 制度が向上し続けている最新LLMの使用。RAG構成により公式情報の引用ベースで生成。根拠提示の徹底。都庁HPの深層階層まで読み取り可能にすることで、FAQ更新負担を軽減。 |
| 多言語誤訳        | 自動翻訳＋言語別テンプレート整備、専門監修         |
| 情報更新の遅れ      | 自動クロール・職員による定期チェック体制          |
| 高齢者のデジタル対応困難 | 既存の窓口を無くすわけではない    |
| プライバシー懸念     | 個人情報入力を制限、ログ保存期間を短く設定       |

### 事例（海外・国内）

- 深圳市：DeepSeek大規模モデルを市全域に導入し、行政・生活支援のAI窓口を整備
   -  [深圳市の事例](https://www.sz.gov.cn/cn/xxgk/zfxxgj/zwdt/content/post_12004270.html)
- 渋谷区：111言語対応のAI総合チャットボットを導入（RAG構成） 
   - [渋谷区の事例](https://www.showcase-tv.com/pressrelease/20221111-cx-shibuya/)
- 会津若松市：LINE上の行政案内Bot「ちゃチャット」により、ごみの分別や休日・夜間診療、防災関連の情報を24時間提供
   -　[会津若松市の事例](https://www.city.aizuwakamatsu.fukushima.jp/faq/)

## 施策２：民間主導の観光DXを加速するデータ連携基盤の整備

### 何をするかの概要

**民間企業が多様なAI観光案内サービス（チャットボット等）を自由に開発・提供できるよう、東京都が保有する信頼性の高い観光関連データを集約し、標準化されたAPI形式（プログラムがデータをやり取りするための接続口）で公開するデータ連携基盤を整備します。**

### 何をするか具体的に

*   **都営交通のリアルタイム運行情報、都立文化施設のイベント情報、公衆トイレ・授乳室・バリアフリー施設の設置場所、観光スポットの基本情報などを集約します。**
*   **データのリアルタイム性や正確性を確保した上で、民間開発者が容易に利用できる標準化されたAPI形式（例: OpenAPI Specification）で提供します。**
*   **データ利用規約や開発者向けガイドライン（品質、更新頻度、推奨される公共的配慮事項など）を策定・公開し、適切なデータ利用を促進します。特に公共性の高い情報（例：災害時の避難情報、バリアフリー情報など）については、その提供と品質維持に都が責任を持ちます。**
*   **民間開発者コミュニティとの連携や、開発を支援するための技術情報提供、相談窓口の設置などを検討します。**

### その提案が良い理由

*   **民間企業の自由な発想と技術力を最大限に活かし、多様で革新的な観光サービスの創出を促進できます。**
*   **サービス間の競争原理が働くことで、品質向上や利用者満足度の向上が期待されます。**
*   **東京都は直接的なサービス開発・運用の負担から解放され、質の高いデータを提供・維持するという、行政だからこそできる役割に注力できます。**
*   **整備されたデータ基盤は、観光分野だけでなく、他の行政サービスや民間ビジネスでの活用にも繋がり、オープンデータ化による経済効果も期待できます。**
*   **利用者のニーズに応じた多様なサービスが生まれることで、観光客の利便性が向上し、満足度向上に繋がります。**

### なぜ観光案内分野なのか

*   観光情報は、「アクセス方法」「営業時間」「イベント情報」など**構造化しやすく、API形式でのデータ提供に適しています。**
*   訪都観光客、特に**初めて訪れる方々は地域情報に詳しくなく、多様な情報ニーズが存在するため、民間企業によるサービス開発の需要が高い分野です。**
*   **信頼性の高いデータ基盤を整備することで、民間投資を呼び込みやすく、観光客の満足度向上や消費拡大を通じた地域経済への波及効果が期待できます。**
*   水道・警察・福祉などの分野と比較して、**万が一、民間サービスで誤情報があった場合のリスクが比較的小さく、データ公開を先行して進めやすい領域です。**

### インパクト

*   **東京都の直接的な職員時間削減効果は限定的ですが、民間サービスによる観光案内所の業務負荷軽減は期待されます。**
*   **民間投資の誘発効果:** （例）**年間 数億円規模の新規サービス開発投資** を期待。
*   **観光客満足度向上・消費額増加による経済効果:** （例）**年間 数億円規模**。
*   **+α：オープンデータ化によるイノベーション促進、都全体のDX推進への貢献。**
*   **算出根拠:**
    *   **民間サービスの効果は変動するため直接的な時間削減の定量化は困難。**
    *   **国内外のオープンデータ活用による経済効果の調査レポートや、類似のデータ基盤整備事業の効果測定事例を参考に、民間投資誘発効果や観光消費への波及効果を推定。** (具体的なレポート名や事例へのリンク追加を推奨)

### コスト

*   **初期費用：5,000万円～1億円程度**（データ収集・クレンジング・標準化、APIプラットフォーム構築、ガイドライン策定、開発者向けポータルサイト構築費用など）
*   **年間運用費：2,000万円～3,000万円程度**（データ更新・保守体制、サーバー・クラウド利用料、API監視、技術サポート・コミュニティ運営人件費など）
*   **試算根拠：国内の類似した自治体向けデータ連携プラットフォームの構築・運用費用や、大規模なオープンデータ基盤の事例（例：公共交通オープンデータ協議会等）を参考に試算。**

### 想定されるリスクとその対処方法

| リスク                         | 対処方法                                                                                                                               |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| **データ品質・鮮度の維持が困難**   | データ収集・更新プロセスを可能な限り自動化・標準化。データオーナーとなる部署を明確にし、品質チェック体制と定期的な監査を実施。民間からのフィードバックを受け付ける仕組みも導入。                               |
| **民間サービスの質・公平性のばらつき** | データ利用ガイドラインで推奨事項（多言語対応、アクセシビリティ配慮、特定事業者への不当な誘導の禁止等）を明記。認証制度や優良事例の紹介、アワード等によるインセンティブ付与を検討。利用者がサービスを比較検討できるような情報提供も考慮。 |
| **APIの不正利用・サーバー負荷集中** | 利用規約を定め、APIキー発行による利用申請・認証プロセスを導入。アクセス流量制限（レートリミット）等の技術的対策を実施。不正利用検知・監視体制を構築。                                                    |
| **提供したデータが十分に活用されない** | 開発者向けドキュメントやサンプルコードを充実させ、分かりやすい情報発信を強化。ハッカソンやアイデアソン等のイベント開催による利用促進、開発者コミュニティとの対話を継続。API仕様や提供データに関するフィードバックを収集し、改善に繋げる。 |
| **個人情報・プライバシーへの懸念**   | **原則として個人情報は含めない。統計情報や施設情報中心とする。** データ公開前に匿名化・汎化処理が適切に行われているか確認プロセスを設ける。利用規約で目的外利用を禁止。                               |

### 事例（海外・国内）

*   **公共交通オープンデータ協議会 (ODPT):** 日本全国の公共交通データを標準化し提供。
*   **DATA.GO.JP:** 日本政府のオープンデータカタログサイト。
*   **G空間情報センター:** 地理空間情報の集約・提供プラットフォーム。
*   **Transport for London (TfL) API (英国):** ロンドンの交通データを公開し、多数の民間アプリ開発を促進。
*   **Singapore Land Authority (SLA) OneMap API (シンガポール):** シンガポールの地理空間データAPIを提供。
